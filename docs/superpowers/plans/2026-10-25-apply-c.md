# Jobs Master BR v1 — C Semi-automatic Applications Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "rodar vagas" round that searches vacancies by itself per platform, prepares up to 10 applications per round (30 per day) as open browser tabs at the last step of each form, and never sends anything.

**Architecture:** Deterministic rules (limits, counters, dedupe, filters, answer bank, fit-test risk flags, platform pauses, status tracking) live in the Python package `jobbot` and its CLI. Browser work is done by Claude Code skills that follow platform notes and call the CLI for every decision that must be exact. Uses A (profile, screening bank), B1 (targets, behavior profile) and B2 (types, `vaga-eval`, `vaga-resume`, PDFs, `applications` log).

**Tech Stack:** Python >= 3.10, PyYAML, pytest, Claude Code skills (Markdown); browser automation through the Claude browser tools; the Claude Indeed connector when present.

**Spec:** `docs/superpowers/specs/2026-10-25-candidatura-c-design.md` (builds on the A, B1 and B2 specs in the same folder)

## Global Constraints

- Product language PT-BR; market Brazil. Code, tests, commit messages in English; user-facing strings and skill bodies in PT-BR.
- The bot NEVER sends an application. Every flow ends on an open tab at the last step. No skill or command may click a final submit/send button.
- Platforms in v1: `linkedin`, `indeed`, `gupy`. Limits per platform: 10 prepared tabs per round, 30 per day (configurable); at most 50 vacancies examined per platform per round.
- Only a successfully prepared tab counts toward limits. Filtered, failed and blocked vacancies do not count. A platform with 10 or more `preparado` applications starts no new round.
- Application statuses (exact): `preparado`, `enviada`, `descartada`, `bloqueada`, `externa`, `desconhecido`. Platform pause persists until released; the day counter resets next day.
- Stop conditions (captcha, verification request, unusual-activity warning, login wall) pause the platform; no retries, no bypass, no parallel sessions, no credentials stored or asked.
- Never answer a form field with an invented value: answers come only from the profile, the screening data or the answer bank. Unknown fields stay blank and highlighted. Sensitive (PCD, gender, race, work authorization) and legal-consent fields are answered only from a saved bank entry.
- Fit tests: modes `auto` (default), `perguntar`, `pular`; live-camera tests are never answered. Risk flags (`proibe_ia`, `cronometrado`, `tentativa_unica`, `vigiado`) go to the review sheet and the round summary.
- External company sites: open the page in a tab, no filling, status `externa`, counted as prepared.
- Dedupe key: URL without tracking parameters (keep the vacancy id parameters `jk`, `vjk`, `currentJobId`, `id`); across different platforms also company + title (normalized).
- Local data only, owner-only permissions (dir 0700, files 0600). Honesty rules of A and B2 unchanged.
- Mandatory notice at round start: "Automação em LinkedIn, Indeed e Gupy viola os termos dessas plataformas. O risco para a conta é de cada pessoa."
- Git: branch `feat/apply-c`, cut from `feat/education-field` (none of the earlier branches is merged; no `main`, no remote). Conventional Commits in English, subject <= 72 chars, explicit paths in `git add`, no `Co-Authored-By`, no push.
- Repo is public: no real person's data, no owner name.

## Review Focus

1. Limit boundaries: 9 vs 10 prepared in a round, 29 vs 30 in a day, each platform counted independently; blocked, failed and filtered vacancies not counted; 10 pending tabs, a paused platform and a day rollover (Task 2).
2. Dedupe: tracking parameters, trailing slash and letter case do not hide a repeat; Indeed `jk` and LinkedIn `currentJobId` stay in the key; the same vacancy on two platforms is caught by company + title, while two different openings of the same company and title on one platform are not wrongly merged (Task 2).
3. Answer matching: "anos de experiência com SQL" never matches the Python answer; sensitive and legal questions are never auto-answered without a bank entry; blank is the default for the unknown (Task 3).
4. Fit-risk detection in Portuguese phrasings, and the action table: `vigiado` always leaves the test to the person (Task 4).
5. State safety: invalid status or platform rejected without changing the file; corrupt profile gives a clean error; pause survives and is released only by command; files 0600 (Tasks 1, 5).

### Task 3: Answer bank

**Files:**
- Create: `jobbot/answers.py`
- Test: `tests/test_answers.py`

**Interfaces:**
- Consumes: Task 1, `match.normalize`, `Profile.screening`.
- Produces:
  - `classify_field(question: str) -> str`: `"sensivel"` for PCD/deficiência, gênero, sexo, raça, cor, etnia, orientação sexual, religião, estado civil; `"legal"` for consent and terms (autorizo, consinto, LGPD, termos de uso, política de privacidade, aceito); else `"geral"` (accent- and case-insensitive)
  - `match_bank(question: str, bank: list[AnswerEntry]) -> AnswerEntry | None`: normalized exact match first; else word-set similarity (Jaccard over words of 3+ letters, ignoring a small stop-word list) >= 0.8, and the two questions must have the same numbers and the same non-stop words in the position of any differing word being absent (practically: questions that differ in a skill name or a number never match); the tests below fix the behavior
  - `builtin_answer(question: str, p: Profile) -> str | None`: from `screening` for salary expectation (`pretensão salarial`), start availability (`disponibilidade`, `quando pode começar`), e-mail, phone, and `anos de experiência (com|em) <skill>` -> `years_by_skill` (normalized skill name); `None` when the profile lacks the value
  - `Resolution(question: str, category: str, status: str, answer: str | None, source: str)` with `status` in `("respondida", "em_branco")` and `source` in `("banco", "perfil", "")`
  - `resolve(questions: list[str], p: Profile) -> list[Resolution]`: order: bank match first; then `builtin_answer` only for category `geral`; sensitive and legal questions are answered only from the bank; everything else `em_branco`
  - `add_pending(p: Profile, questions: list[str], vaga: str, today: date) -> None` (dedupe by normalized question; only `em_branco` ones) and `upsert_answer(p: Profile, entry: AnswerEntry) -> None` (replaces by normalized question; removes the question from `p.pending`)

### Task 4: Fit-test risks and behavior summary

**Files:**
- Create: `jobbot/fit.py`
- Test: `tests/test_fit.py`

**Interfaces:**
- Consumes: Task 1, `Profile.assessments`, `Profile.behavior`.
- Produces:
  - `FLAGS = ("proibe_ia", "cronometrado", "tentativa_unica", "vigiado")`
  - `fit_risks(text: str) -> list[str]`: PT-BR regexes over normalized (accent-free, lowercase) text. `proibe_ia`: "sem (o )?(uso|ajuda) de (ia|inteligencia artificial|chatgpt)", "nao (e permitido|use|utilize) .{0,30}(ia|inteligencia artificial|chatgpt)", "proibido .{0,20}(ia|inteligencia artificial)". `cronometrado`: "tempo (limite|maximo|total)", "\d+ minutos", "cronometro", "temporizador". `tentativa_unica`: "(unica|uma so) tentativa", "nao (podera|sera possivel) refazer", "apenas uma vez". `vigiado`: "camera", "monitorad", "proctor", "gravacao da tela", "reconhecimento facial". Result in `FLAGS` order, no duplicates.
  - `fit_action(mode: str, flags: list[str]) -> str`: `"deixar_para_pessoa"` when `vigiado` is present (any mode); else `"pular"` for mode `pular`; `"perguntar"` for mode `perguntar`; `"responder"` for mode `auto`
