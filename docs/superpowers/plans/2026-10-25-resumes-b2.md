# Jobs Master BR v1 — B2 Job Types and Resumes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn accepted professions into job types with their own rules, and generate truthful, ATS-friendly PDF resumes: one model per type, a light per-vacancy tailoring, and a from-scratch resume for good vacancies that fit no type.

**Architecture:** Same shape as A and B1. Deterministic logic (posting validation, job-type rules, classification, evaluation, resume document, PDF writer) in the Python package `jobbot`, exposed through CLI commands. The model (the Claude Code skill) extracts structured fields from a vacancy and writes only the wording of summary and bullets; every employer, role, date, degree and certification is rendered from profile fields. Two new skills drive the flow.

**Tech Stack:** Python >= 3.10, PyYAML, `fpdf2` (PDF, pure Python, offline), pytest, `pypdf` (dev only, text extraction in tests), Claude Code skills (Markdown).

**Spec:** `docs/superpowers/specs/2026-10-25-curriculos-b2-design.md` (builds on A and B1 specs in the same folder)

## Global Constraints

- Product language PT-BR; market Brazil. Code, tests, commit messages in English; user-facing strings and skill bodies in PT-BR.
- Personal data 100% local; profile dir 0700, every file written by B2 (YAML, PDF, review sheet) 0600.
- Honesty (A's rule, extended): never invent employer, role, date, degree, certification or result number. Employer, role, dates, certifications come only from profile fields; the model writes only summary and bullet wording; numbers in any model-written text must pass `unsupported_numbers`.
- A stretched skill appears only in the Competências list: no level, no experience claim, never in summary or bullets. Below 50% match ("arriscada") nothing is stretched.
- Never generate hidden or invisible text, image text, tables, columns, icons or photos. The PDF's extracted text must equal the document text.
- PDF: selectable text, single column, headings exactly: Resumo, Experiência, Projetos e voluntariado, Competências, Certificações, Idiomas. Empty sections are omitted.
- Match labels, stretch policy and group rules are A's and B1's, unchanged. "Vaga boa" (no type): match >= 70, modality and contract within the person's constraints, salary >= the lowest effective floor among types (salary not informed passes with a note). Below the floor is flagged "abaixo do piso", never discarded. A tie between types is "ambiguo" and the person chooses; B2 never picks.
- A job type exists only for a releasable target: `orientation.cv_released` with the target's current `projected_match` (B1 rule). `cv_released` is computed, not stored.
- Summary: at most 480 characters (4 lines).
- Git: branch `feat/resumes-b2`, cut from `feat/orientation-b1` (neither merged; no `main`, no remote). Conventional Commits in English, subject <= 72 chars, explicit paths in `git add`, no `Co-Authored-By`, no push.
- Repo is public: no real person's data, no owner name.

## Review Focus

1. PDF text integrity: accents (ç ã é), dashes, bullets and curly quotes survive or map to safe characters; a character outside Latin-1 (an arrow, an emoji) never crashes the run and never silently changes meaning; extracted text equals the document text (Task 5).
2. Stretched-skill leak: a stretched skill named in the summary or a bullet is rejected; a "arriscada" vacancy produces a PDF with zero stretched skills; the review sheet lists what is missing (Tasks 4, 6).
3. Type edge cases: no types defined, a target that is not releasable cannot become a type, a tie returns "ambiguo", a vacancy with an empty skills list gives a clear error and not a `ValueError` traceback (Tasks 2, 3).
4. Salary and constraint edges: salary missing passes with a note, below floor is flagged and kept, floor missing means no check, empty `constraints.modality` means any modality, contract "ambos" accepts both (Task 3).
5. Files and log: generating twice for the same vacancy and day makes two distinct files and two log records, never overwrites; company and title with `../`, accents or empty text give safe file names; permissions 0600/0700 (Task 6).

### Task 3: Classification and evaluation

**Files:**
- Create: `jobbot/classify.py`, `jobbot/evaluate.py`
- Test: `tests/test_classify.py`, `tests/test_evaluate.py`

**Interfaces:**
- Consumes: Task 2, `match.normalize`, `match.label`, `match.stretch_action`, `orientation.projected_match`.
- Produces in `classify.py`:
  - `Classification(kind: str, role: str | None, candidates: list[str], scores: dict[str, int])` with `kind` in `("tipo", "ambiguo", "sem_tipo")`
  - `classify(posting: Posting, p: Profile, forced: str | None = None) -> Classification`: for each defined type that is still releasable, `keywords = type.keywords + target.required_skills`; `score = number of normalized posting skills found in keywords + 2 if any title word (>= 4 letters, accent-stripped, lowercase) of the role appears in the posting title`. Best score >= 2 and unique -> `tipo`; tied best -> `ambiguo` with `candidates`; best < 2 or no types -> `sem_tipo`. `forced` must name a defined, releasable type, else `ValueError`; it returns `tipo` directly.
- Produces in `evaluate.py`:
  - `Evaluation(match: int, label: str, action: str, missing: list[str], stretched: list[str], risky: bool, below_floor: bool, constraints_ok: bool, good_without_type: bool, notes: list[str])`
  - `evaluate(posting: Posting, p: Profile, type_role: str | None) -> Evaluation`: empty `posting.skills` -> `ValueError("vaga sem lista de skills")`; `match, missing = projected_match(p, posting.skills)`; `action = stretch_action(match, p.stretch_policy)`; `stretched = missing` when action is `esticar` or `esticar_marcado`, else `[]`; `risky = match < p.stretch_policy.risky_below`; `below_floor` uses the type's effective floor when `type_role` is given, otherwise `False`; `constraints_ok` checks modality (empty `constraints.modality` = any) and contract (`""` or `ambos` = any); `good_without_type` = match >= 70 and `constraints_ok` and (salary missing or salary >= lowest effective floor among defined types, or no floors at all). Missing salary adds the note "salário não informado".

### Task 7: Skills and reference

**Files:**
- Create: `skills/jobbot-types/SKILL.md`, `skills/jobbot-resume/SKILL.md`, `references/resume-writing.md`
- Modify: `tests/test_skills.py`

**Interfaces:**
- Consumes: CLI commands from Task 6 and B1's `targets`. Each skill: frontmatter `name` equal to folder, PT-BR `description` with trigger phrases.

Content each skill must carry:
- **jobbot-types:** prerequisites (valid profile, at least one target; `type-list` shows which are `liberado`); for each releasable target asks for salary floor, modality and contract overrides (explaining the defaults) and writes `type.yaml` for `type-define`; for each defined type writes the content YAML (summary of at most 480 characters, bullet wording per employer and per project, `skill_order` with the type's keywords the person owns) following `references/resume-writing.md`, runs `type-resume`, shows the PDF path and asks the person to review it; for people without formal experience in the area, uses projects with `kind` (`autodidata`, `voluntariado`) and `start`, asking only for facts and numbers the person gives.
